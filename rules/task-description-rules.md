# Task description rules

## Steps and QC check
- At most 5 action steps. No Check step inside the steps.
- Each step names the item, its zone, the action and the visible result.
- Steps are always done in the written order.
- Write the steps first. The instruction (one sentence naming the result), Target State, QC check, Pass and Fail are traced from the steps.
- Separate column "QC check, step by step": one line per step, same order, same words. It asks only what that step did.
- Pass = all lines true. Fail = the opposite of any line.
- Mid-task results can be QC check lines (e.g. the liquid reaches the line before the cap goes on).
- Every item touched ends with its zone and how it lies (upright, flat, open side up, closed), and that end position comes from a step.
- A step or check never claims a result no step made. Items that do not move are only named to locate them, as in the Initial State.

## Wording
- Full item name and its zone every time an item could be confused. No "it" between two items.
- One name per item, from the Asset Pool.
- Every placement says how it ends: "until it stands upright in the rack", "place it flat on the mat".
- Every "until" ends at something visible: taped line, until it stops, edges meet, full turns, a count in a row.
- Banned: firmly, neatly, properly, all the way, around, about, some, as needed, if.
- Banned verbs from old workbooks: carry, tilt, lift, set down, let go, slide. Also no grab spots, no old robot values (40 mm, 40 cm), no mistake starts, no instruction made of joined steps, no mat colours.
- Approved new words: button, unbutton, zip, unzip, stack, hang, coil. "Wrap ... full turns around" replaces "wind".
- Arms are never named. Reverse tasks are titled "Reset: ...".
- Use the general word people use for a job ("button a shirt").
- Office-only tools are called by the name printed on them or by colour (JAYO box, INGCO, WISEUP, RIVER, Bosch, Ryobi, red screwdriver, ANENG, TP-Link, Labshark).
- Hard case: "close it shut", not "zip it".
- No task starts with a mistake. Repair and swap tasks are worded as replace or exchange jobs.

## Pass, Fail and Keep Rules
- Pass names the zones that become empty because a step moved an item out.
- Fail names concrete wrong results (on its side, outside the rack, cap off, still in its start zone), not just "not done".
- Keep Rules: one or two task-specific handling tips, then the standard "If something goes wrong" sentence.

## Bench and start states
- Start shapes are plain only: upright, flat, open side up, cap off, closed. Never curled, partly stuck or raised corners.
- Before-Record Checklist mirrors the Initial State line by line, in setup order.
- A forward task ends exactly where its reverse starts.
- Holes change each episode (step says "an empty hole").
- Variety comes from start pose changes and grab styles. Never written in a task row, never judged by QC.
- Dominoes in counts of 10 (2 rows of 5) or 20 (4 rows of 5).
- No filler: one task per kind of job, never two tasks that differ only in colour.

## Liquids
- Red or blue only, set per episode in Allowed Colors and Types. Never a separate task.
- Endpoint order of preference:
  1. Natural endpoint with no mark (pipette empty, source empty, full to the shoulder)
  2. The container's own printed graduation
  3. Tape, only where there is no printed scale and a partial level is the point of the task

## Tubes and cryoboxes
- The 15 mL tube does not stand on its own: put it in its rack hole before filling or closing. No row holds a tube upright by hand.
- Closing a rack tube: put the cap on the open tube in the rack, take the tube out, close it, put it back in its rack. Same pattern for all liquid tubes, including 2 mL cryo tubes (take out of the box, cap on, close, back in a well whose number the task states).
- Cryobox wells are stated by number, corner wells only: 81-hole box wells 1, 9, 73, 81; 25-hole box wells 1, 5, 21, 25. Printed numbers read left to right, row by row.

## Workbook parts
- Setup Notes include a tool test before recording (e.g. one pipette fill reaches the tape, the cap turns on).
- Scene Spec has "Containers and how to read them": layout of every rack, cryobox, compartment box, organiser, tin, reel, white board, hard case.
- Asset Pool: short name, standard colour, allowed changes, size, material, how to hold it, what it is used for, handling notes. Each colour is its own item.
- Task Families: How to Do It Well, Variations Covered, Common Mistakes.
- README opening line: instruction, steps, start state, end state and checks all say the same thing; if two disagree, stop and tell the Description Manager.
- README lists items and sizes to test on the rig, and ends with a change log, how the version was checked, and points for the Description Manager.
- No reject codes, no QC upload fields, no camera rules, no pictures unless clearly good.

## Checking
- Run every test after each change. Re-read after every 10 descriptions.
